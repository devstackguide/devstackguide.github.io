Is custom tasks in .NET suitable for large teams?

It scales well precisely because it standardizes the everyday workflow. The larger the team, the more value you get from shared configuration, enforced conventions, and a single documented setup path.

Where should shared build settings live?

Directory.Build.props for evaluation-time properties and Directory.Build.targets for execution-time customization, at the repository root — MSBuild imports them automatically for every project beneath.
